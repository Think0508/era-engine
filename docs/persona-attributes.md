## 一、决策链（为什么不是五度）

2026-08-21 曾落地「五度」机制通电（屈服度/软弱度/欲望度 三属性 + `accumulate_degrees` 统一累加通道，
单调不降、永久累计）。2026-08-25 grill 撤销，原因：

1. **量级不可统一**：好感度 cap 100000、信赖度 cap 300（单次增量差 ~60 倍）；三个新度的候选来源流
   （屈服/恭顺/羞耻 日累计千~万级、恐怖/苦痛 千级、绝顶 十~百级）彼此再差 2~3 个数量级——「5 度同数量级」
   既做不到也无必要（组合判定应走 erArk 等级加成模式，但那会再造一个系统）。
2. **镜像 = 换皮计数器**：欲望度/屈服度若只是既有流（经验/params/刻印）的镜像，与 counter-system、
   h-mark 冗余。
3. **单调铁律自相矛盾**：设计裁定五度单调不降，内容层却计划「威胁扣好感/信赖」。
4. **数值规律前置（角色性格系数系统）0 设计**，关键路径被未知系统卡死。

**替代裁定**：只保留「好感度 / 信赖度」（现成，不动）；其余全部取消，改为 **3 个静态人设属性**。

## 二、三属性语义与用途

| 属性 | 语义 | 对抗的胁迫类型 |
|------|------|---------------|
| 坚强度 | 抗威胁/胁迫的意志 | 威胁 → 对抗 坚强度 |
| 道德感 | 遵循道义良知的程度 | 哄骗 / 违背道义 → 对抗 道德感 |
| 贞操观 | 对性事的保守程度 | 淫猥 / 性胁迫 → 对抗 贞操观 |

组合判定（将来的威胁/绑架/哄骗指令）= 三轴 + 好感/信赖等级 + 当日状态（erArk 实行判定公式的形状），
三轴为正交的人设系数，不参与任何数值成长。

## 三、刻度约定（作者约定，引擎不钳制）

- **默认 50 = 常人中性**（attributes.toml default=50；角色不写该字段即 50，机制同 好感度 default=30）
- **0 = 完全无此特质**（毫不坚强 / 无道德感 / 无贞操观）
- **100 = 极强**（极坚强 / 极有道德感 / 极贞洁）
- **负值 = 夸张反向人设**（比"完全无"更夸张的软弱 / 无道德感 / 放荡——为特殊人设预留）
- 可正可负、无运行时上限下限；条件阈值由指令作者按此刻度自定（如 `>= 70` 算坚强的人，`< 30` 算软弱）

## 四、存放位置与回退链

与其他属性同表同机制（`base = {...}` 一张表）：

- named：`characters/named/令狐冲/base.toml` → `base = { "坚强度" = 80, "道德感" = 90, "贞操观" = 85 }`
- 批量：`characters/roster.toml` 条目同名 `base = {...}`
- 模板：`templates/character/*.toml` 可给整批角色预设（如「江湖人士」模板 道德感 30）
- 路人：`npc.toml` 的 `overrides`

回退链（引擎现成）：**角色写的 → 模板 → attributes.toml default（=50）**。

条件路径（声明即注册）：`character.{id}.坚强度`、`character.{id}.道德感`、`character.{id}.贞操观`。

## 五、边界声明（与既有机制的分工）

| 机制 | 结论 |
|------|------|
| `talents.toml`「坚强 / 脆弱」天赋 | **保留不动**（max=1，恭顺/屈服结算系数微调，与判定无关）；若将来想打通「属性 坚强度 ≥ X 自动视为素质坚强」，另行立项 |
| ABL「欲望」能力（ability 33） | 好色倾向轴，维持现状，不回卷「欲望度」 |
| 屈服刻印（h-mark） | 单日高峰账（阈值 30000/50000/100000），维持现状，不回卷「屈服度」 |
| 好感度 / 信赖度 | 现成 social 属性，不并入人设轴 |

## 六、稀有事件改人设（供内容层作者）

人设默认静态；若剧情需要「极少数事件」改动（如某次剧变后 坚强度 -20）：

- **用 `set_attribute`**（直接设值，不钳制、可写负值）：`{ type = "set_attribute", params = { attr = "坚强度", value = 30 } }`
- ⚠️ **不要用 `modify_attribute` 减到负**：`settlement.applyChange` → `clampAttrValue` 先 Math.max(0,…)，
  负方向会钳到 0，进不了负半轴（`_default` cap 99999 同理）。
- 若未来需要属性级 min/max（±100 钳制），另行立项（attributes.toml schema 扩展）。

## 七、引擎限制与能力（作者须知）

- 条件引擎**支持负数字面量**（2026-08-25 起：`-` 后紧跟数字即负数）：`character.{id}.道德感 == -30`、
  `character.{id}.贞操观 >= -50` 直接合法。
- **二元算术仍禁止**（`a - b` / `a + b` 等报错）——复杂逻辑走 `condition_script` / 专用 effect，
  本能力只放行「符号+数字」这一种写法，不改变既有合法表达式的语义。
