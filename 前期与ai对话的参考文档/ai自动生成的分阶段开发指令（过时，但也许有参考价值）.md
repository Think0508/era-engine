## 使用前先看：整体要求（第一阶段前先给它）
先把这段整体要求发给 Claude Code，定好总基调：

```
我要开发一个现代 Web 版的文字 MUD 游戏引擎，对标 EmuERA（日式文字养成/战斗引擎），主打数据驱动、插件化、多端适配、AI 友好。

## 核心技术栈（必须严格使用）
- 前端框架：Vue 3 + Vite + TypeScript
- 状态管理：Pinia
- UI 样式：Tailwind CSS
- 组件库：Naive UI
- 数据格式：toml（所有游戏内容数据统一用 toml）
- 本地存储：Dexie.js（封装 IndexedDB 做存档）

## 核心设计原则（必须严格遵守）
1. 引擎与内容彻底分离：引擎只提供能力，所有世界观、角色、剧情都放在独立模组包中
2. 插件化玩法系统：所有玩法（战斗、采集、商店等）都是独立插件，即插即用，新增/删除不修改引擎内核
3. 数据驱动：能用配置实现的绝不写死代码，所有内容都可以通过改 toml 实现
4. 分层解耦：数据层、逻辑层、UI 层严格分离，修改任意一层不影响其他层
5. AI 友好：所有数据格式标准化、语义化，避免编号索引等反人类设计
6. 响应式优先：一套代码同时适配 PC 宽屏和手机竖屏，移动端体验优先

## 第二阶段：核心数据系统实现

### 任务目标
实现模组加载系统、跨文件模板继承系统、实体管理系统，这是整个引擎的数据地基。

### 具体要求

#### 1. 模组加载系统（src/core/mod-loader.ts）
- 支持从 mods/ 目录加载模组
- 每个模组有 meta.toml 作为元信息，包含：id、name、version、author、description、dependencies（依赖的插件/模组）
- 支持多模组叠加加载，数据自动合并
- 支持模组依赖检查，依赖缺失时给出明确报错

#### 2. 模板继承系统（src/core/template.ts）
- 实现多级跨文件模板继承机制
- 支持 extends 字段指定父模板，可以多层继承（A 继承 B，B 继承 C）
- 子模板/子角色只写差异属性，自动合并父模板的所有属性
- 支持属性覆盖、数组合并、对象深合并
- 模板文件统一放在 mods/[模组]/templates/ 目录下
- 角色模板放在 templates/character/ 下，物品模板放在 templates/item/ 下

#### 3. 实体管理系统（src/core/entity-system.ts）
- 统一管理所有游戏实体（角色、物品、天赋、技能等）
- 每个实体有唯一 ID，通过 ID 快速查询
- 支持从模组 toml 文件自动加载实体
- 角色实体支持：基础属性 base、天赋 talents、能力 abilities、关系 relations
- 角色单文件单角色，放在 mods/[模组]/characters/[分类]/[角色ID]/base.toml
- 物品/天赋/能力定义放在 mods/[模组]/definitions/ 下，分别对应 talents.toml、abilities.toml、items.toml

#### 4. 数据校验工具（src/utils/validator.ts）
- 加载数据时自动校验格式合法性
- 字段类型错误、ID 重复、模板不存在等问题，给出精准报错（文件名 + 行号 + 错误原因）
- 校验不通过时阻止加载，避免静默失败

### 验收标准
1. 能正确加载示例模组的 meta.toml
2. 能正确加载三级角色模板（基础人类 → 职业 → 具体角色），属性正确合并
3. 能通过 ID 查询到角色、物品、天赋等实体
4. 模板继承正确：子角色没写的属性自动用父模板的，写了的覆盖父模板
5. 故意写错数据格式，能给出清晰的错误提示，包含文件名和错误位置

### 输出
- src/core/ 下的核心模块文件
- 示例模组里的测试模板和测试角色数据
- 能在控制台打印出加载成功的实体列表

## 第三阶段：条件系统、事件总线与全局属性字典

### 任务目标
实现通用条件表达式解析、事件总线系统，以及自动生成的全局属性字典，这是所有系统联动的基础。

### 具体要求

#### 1. 条件表达式解析器（src/core/condition.ts）
- 支持极简表达式写法，如：player.base.hp < 30
- 支持的运算符：> < >= <= == != && || !
- 支持括号分组，如：(player.base.hp < 30 || player.base.mp < 20) && location.id == "test_room"
- 支持字符串值，用双引号包裹，如：location.id == "huashan_shop"
- 表达式从全局上下文中取值，自动解析属性路径
- 解析失败时给出精准错误提示

#### 2. 事件总线（src/core/event-bus.ts）
- 实现发布订阅模式的事件系统
- 支持 on/off/once/emit 基本方法
- 支持按事件名监听和触发
- 事件触发时携带参数
- 所有系统之间的联动都通过事件总线，不直接互相调用

#### 3. 全局属性字典（src/core/condition-registry.ts）
- 统一管理所有可用于条件判断的属性字段
- 每个字段包含：path（属性路径）、name（中文说明）、type（数据类型）、operators（可用运算符）、source（所属系统）
- 提供注册接口，各系统/插件自动注册自己的字段
- 引擎启动时自动汇总所有注册的字段，形成完整字典
- 自动导出一份 Markdown 格式的《可用条件属性手册》，生成在项目根目录，文件名：可用条件属性手册.md
- 手册内容为表格形式，包含：属性路径、中文说明、数据类型、可用运算符、所属系统
- 每次启动项目时自动更新这份手册，确保永远是最新的

#### 4. 游戏上下文（src/core/game-context.ts）
- 统一的全局游戏状态容器，供条件表达式取值
- 包含但不限于：player（玩家属性）、location（当前地点）、game（游戏时间等全局状态）、character（角色属性，支持通过ID访问）
- 数据变化时自动更新，条件表达式能拿到最新值

### 验收标准
1. 能正确解析各种复杂的条件表达式，返回布尔值
2. 事件总线能正常监听和触发事件，参数传递正确
3. 各系统能注册自己的条件字段到全局字典
4. 项目根目录自动生成《可用条件属性手册.md》，内容完整、格式清晰
5. 修改插件/增减字段后，手册自动同步更新
6. 条件表达式能正确从游戏上下文中取值判断

### 输出
- src/core/ 下的对应核心文件
- 自动生成的属性字典手册
- 测试用例验证条件解析正确性
```
