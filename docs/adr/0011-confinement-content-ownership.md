# 监禁系统：地点/道具/数据归属（ADR 0011）

2026-08-14 决策。复刻 erArk 监禁系统时，确定各数据段归属哪一层（插件默认层 vs mod 内容层）。这是自研 mod 会频繁改动的地方，记录决策考虑供后续参考。

## 背景

erArk 中监禁设施（牢房/调教室/监狱长办公室）、携袋道具（Item 151）、训练设置（CSV）都是游戏系统数据。但我们引擎的三层架构（core/plugins/mods）要求：**插件提供通用机制 + 默认数据，mod 提供世界观内容**。判断标准：这份数据是否包含世界观专属语义？

## 决策

| 数据 | 归属 | 理由 |
|------|------|------|
| 牢房/调教室/监狱长办公室/休息室 | **mod 地图**（maps/locations/） | 地图是世界观内容的天然载体；不同世界观监狱形态完全不同（武侠地牢 vs 魔法监狱） |
| 携袋道具 | **插件默认层** `data/default/items/bag.toml` | erArk 中它是系统道具（非世界观名物）；插件提供通用「携袋」，mod 可 override 改名/图标/描述 |
| 训练模式（6 种） | **插件默认层** `data/default/training.toml` | 训练类型是玩法机制（快感/扩张/苦痛/技巧/锻炼/服从），跨世界观通用 |
| 设置初始值 | 插件代码 DEFAULT_SETTINGS | 纯机制默认值 |

## 插件消费的 tag 约定（mod 建模要求）

- `prison`：牢房（投牢目标点、空牢房分配扫描）
- `detention`：关押区区域标记（逃犯藏匿点排除）
- `humiliation_room`：调教室（调教前准备移动目标）
- `warden_office`：监狱长办公室（预留）
- `warden_rest`：监狱长宿舍（任命时搬入）

插件**不提供任何地点数据**——tag 约定是插件与 mod 之间的契约（sleep-system 消费 `has_bedroom` tag 同款模式）。

## 备选方案

1. 插件默认层提供标准监狱地点集（牢1-牢8 等）——插件层引入世界观内容，违背三层分离，否决
2. 牢房数硬编码（erArk 8 间）——引擎不硬编码，地点由 mod 定义，否决

## 影响

- mod 接入监禁系统的必做清单：建监狱地点（带 tag）+ 定义携袋（或 override 插件默认）
- test-mod 已提供微型关押区（走廊+牢1/牢2+调教室）作为参考实现
- 后续自研 mod 改监狱布局/道具 = 纯 TOML 改动，引擎零改动
