# 尿道：引擎泛化支持，默认内容不做（方案A）

2026-08-08 决策。此前 spec 决策 #13 把尿道整体砍掉（19 条尿道指令 + 无感度/无绝顶）。审查发现尿道快感属性/指令引用一直存在但静默失效（感度能力缺失 → 系数恒 1.0、不入绝顶），且用户重新评估后认为尿道玩法"不够常用不够色"，保持内容层不做。最终方案：

- **引擎层完整支持**：ORGASM_PART_ATTR 含 partId 6、ORGASM_PART_SENSITIVITY/PART_PREFIX/PART_EXP_ID 齐全、pain_by_part/feel_by_sex 含 U 部位参数（base=1000/偏移 -3）——与 erArk part 表完全对齐，零死代码
- **默认数据不定义** 尿道感度/尿道扩张 能力，UI 隐藏（attributes.toml 尿道 display=false），尿道指令保持砍掉
- **启用路径**：mod 想支持尿道 = 在 abilities.toml 定义 尿道感度/尿道扩张 + 写指令 TOML，引擎零改动

权衡：相比"彻底移除尿道属性"（需存档迁移、与 erArk 数据模型产生差异）和"完整恢复尿道内容"（用户不想要），方案A 在存档兼容、数据对齐、内容取舍之间取得平衡。曾考虑彻底移除，因迁移成本与引擎-蓝本差异被否决。

Status: accepted
