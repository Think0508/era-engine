# 文字MUD游戏引擎 架构与开发规范总览
本文档为项目唯一架构标准，所有开发与内容制作严格遵循本规范。核心设计原则：**引擎与内容彻底分离、玩法插件化可插拔、数据驱动优先、AI友好、主题与功能解耦**。

---

## 一、三层核心架构（边界绝对清晰）
整体采用「内核-插件-模组」三层解耦架构，下层只提供通用规则，上层填充具体内容；下层永远不依赖上层，上层可自由替换。

### 1. 引擎内核层（`src/core/`）
- **定位**：纯通用机制空容器，不包含任何具体玩法、任何世界观、任何视觉风格内容。
- **核心职责**：提供底层基础工具与运行规则，是所有插件与模组的公共底座。
- **边界禁令**：
  - 禁止出现背包、战斗、技能、角色等具体玩法概念；
  - 禁止预设任何属性名、字段名、分类名；
  - 禁止写入任何美术样式、视觉相关的固定值。
- **类比**：空白的Excel软件本身，只提供表格、公式、宏的通用能力。

### 2. 插件玩法层（`src/plugins/`）
- **定位**：独立功能模块，基于内核实现某一类具体玩法逻辑，不含具体世界观数值与内容。
- **核心职责**：实现玩法规则，注册功能到公共API，注册UI到插槽，通过事件与其他插件联动。
- **关键特性**：
  - 即插即用：单个插件可独立启用/禁用，禁用后无数据残留、不影响其他功能；
  - 多套并存：同类型玩法可存在多套独立实现（如武侠战斗、魔法战斗、卡牌战斗），模组按需选用；
  - 零直连：插件之间禁止直接调用内部代码，只能通过公共API + 事件总线通信。
- **类比**：Excel里做好的功能模板（财务模板、成绩模板），定好了列和公式，但没有具体数据。

### 3. 模组内容层（`mods/[模组名]/`）
- **定位**：纯内容与主题包，填充具体世界观、角色、数值、剧情、美术风格。
- **核心职责**：提供所有游戏内具体内容，声明依赖的插件，定义专属美术主题。
- **边界禁令**：不包含引擎核心逻辑；复杂逻辑仅能通过受限沙箱脚本实现。
- **类比**：填好具体数据的Excel表格 + 皮肤主题，换模组=换游戏内容与画风。

## 二、技术栈选型与分工
| 分类 | 技术选型 | 核心作用 | 所属层级 | 备注 |
|------|----------|----------|----------|------|
| 核心框架 | Vue 3 + TypeScript | 前端组件化开发，类型安全 | UI层 + 插件层 | 全项目统一 |
| 构建工具 | Vite | 项目构建、热更新、打包发布 | 工程层 | 官方标配 |
| 状态管理 | Pinia | 全局响应式状态管理，数据自动同步UI | UI层 | 仅用于UI状态同步 |
| 样式方案 | Tailwind CSS + CSS变量 | 原子化样式，支持主题动态切换，响应式适配 | UI层 | 所有样式基于主题变量实现 |
| 组件底座 | Naive UI | 通用功能组件（弹窗、表单、表格） | UI层 | 仅用于辅助界面，核心游戏界面全定制，样式深度覆写 |
| 数据解析 | @iarna/toml | 解析TOML数据文件，统一转为JS对象 | 内核层 | 主力数据格式，兼容YAML作为可选 |
| 本地存储 | Dexie.js | 封装IndexedDB，实现多存档、大容量存储 | 内核层 | 按命名空间隔离数据 |
| 工具函数 | VueUse | 常用Vue组合式工具，减少重复代码 | 工具层 | 按需引入 |
| 脚本执行 | 自定义沙箱 | 安全执行模组自定义JS脚本 | 内核层 | 可选进阶，默认关闭 |

### UI分层原则
1. **核心沉浸区（90%用户时间）**：主场景、战斗、对话、地图、角色详情 → 全定制开发，纯Tailwind实现，无组件库痕迹，打造游戏化美术风格；
2. **辅助功能区**：设置、存档、开发者面板、确认弹窗 → 基于Naive UI开发，通过主题系统统一视觉风格。

## 三、核心底层机制（按重要性排序）
### 1. 模组加载与模板继承系统
- **能力**：多模组叠加加载、依赖检查、多级跨文件模板继承、差异属性自动合并。
- **关键设计**：
  - 支持无限层级继承，子项仅写差异字段，自动深合并父项属性；
  - 内置循环继承检测，发现死循环直接精准报错（文件+行号+继承链）；
  - 模板与实体数据结构完全一致，无特殊语法；
  - 模组加载时自动校验依赖的插件是否存在，缺失则给出明确提示。
- **所属层级**：引擎内核层

### 2. 通用实体管理系统
- **能力**：统一管理所有游戏实体，支持按类型注册、按ID快速查询。
- **关键设计**：
  - 实体类型完全可扩展，插件可注册新类型（如城池、坐骑），内核不预设任何实体分类，所有类型由插件/模组定义；
  - 自动校验ID唯一性，同类型内重复ID直接报错；
  - 不同类型实体分池存储，跨类型重名无冲突。
- **所属层级**：引擎内核层

### 3. 全局事件总线
- **能力**：发布订阅模式的事件系统，是插件之间联动的唯一通道。
- **关键设计**：
  - 全局标准事件命名规范：格式统一为 `领域:动作`，如 `item:added` `combat:hit` `location:enter`；
  - 支持事件优先级、事件取消、通配符监听；
  - 插件自定义事件必须加插件名前缀，如 `potion:brewed`，避免命名冲突；
  - 所有事件参数有明确类型定义。
- **所属层级**：引擎内核层

### 4. 公共API注册与调用机制
- **能力**：统一的功能调用入口，所有插件只能通过公开API访问游戏能力。
- **关键设计**：
  - 内核仅提供API注册器与基础能力，不预设任何具体玩法API；
  - 插件通过 `api.registerModule()` 将自身功能注册到全局API；
  - 同类型插件遵守统一基础接口规范（如所有战斗插件都必须实现 `startBattle()`），确保切换插件不影响上层逻辑；
  - 严格访问边界：插件无法访问内核内部状态，只能调用公开API。
- **所属层级**：引擎内核层

### 5. 条件表达式解析与全局属性字典
- **能力**：解析极简条件表达式，自动汇总所有可用条件字段，生成可读文档。
- **关键设计**：
  - 表达式语法：支持 `> < >= <= == != && || !` 与括号分组，接近自然语言；
  - 字段自动注册：插件自动注册自身的条件字段，引擎自动汇总；
  - 自动生成手册：启动时自动生成《可用条件属性手册.md》，包含字段路径、说明、类型、可用运算符、所属系统；
  - 字段增删自动同步手册，永远与当前启用功能一致；
  - 非法字段精准报错，提示可用字段列表。
- **所属层级**：引擎内核层

### 6. 统一效果系统
- **能力**：全游戏通用的效果执行框架，物品、技能、天赋、任务、buff共用同一套逻辑。
- **关键设计**：
  - 标准效果格式统一：`type` + 参数，如回血、加属性、加物品、学技能；
  - 效果类型可扩展，插件可注册新效果类型，无需修改内核；
  - 所有效果执行触发标准事件，支持其他插件监听扩展；
  - 支持条件触发效果，满足条件才执行。
- **所属层级**：通用插件层

### 7. UI插槽与主题系统
- **能力**：插件UI自动挂载，主题动态切换，模组可完全替换视觉风格。
- **关键设计**：
  - 预定义命名插槽：主菜单、场景顶部、底部指令栏、角色详情、背包菜单、开发者面板等；
  - 插件可注册组件到插槽，支持优先级排序，禁用时自动移除；
  - 主题基于CSS变量实现：颜色、字体、圆角、间距全部通过变量控制；
  - 模组可自带 `theme.toml`（基础变量）+ `theme.css`（自定义样式），加载时自动注入，卸载时自动移除，不同模组主题互不污染；
  - 所有核心UI与组件库样式全部绑定主题变量，换主题一键生效。
- **所属层级**：UI框架层

### 8. 多命名空间存档系统
- **能力**：多存档位、自动存档、导入导出，插件数据安全隔离。
- **关键设计**：
  - 存档按命名空间隔离：内核、玩家、各插件数据独立存储；
  - 插件只能读写自身命名空间的数据，互不干扰；
  - 插件卸载时可选择清理对应数据，无垃圾残留；
  - 存档版本号机制，支持结构自动迁移，避免版本更新损坏存档；
  - 支持手动存档、关键节点自动存档、JSON导入导出。
- **所属层级**：引擎内核层

### 9. 沙箱脚本执行机制（可选进阶）
- **能力**：安全执行模组自定义JS脚本，支持动态属性、复杂AI、特殊事件。
- **关键设计**：
  - 沙箱环境隔离：无法访问DOM、全局对象、内核代码，仅能调用受限公共API；
  - 超时保护：防止死循环卡死游戏；
  - 错误自动捕获：脚本报错仅影响对应功能，不崩溃全局；
  - 固定钩子入口：角色属性、台词、行为三类标准钩子，与静态TOML文件一一对应。
- **所属层级**：引擎内核层（可选）

## 四、模组内容体系（日常制作规范）
### 1. 标准目录结构
```
[模组名]/
├── meta.toml                  # 模组元信息：名称、版本、依赖的插件、作者
├── theme.toml                 # 主题配置：颜色、字体、圆角等基础变量
├── theme.css                  # 【可选】自定义样式：纹理、边框、动画等精细效果
├── templates/                 # 模板库（多级继承源头）
│   ├── character/             # 角色模板
│   └── item/                  # 物品模板
├── characters/                # 角色库（单角色单文件夹）
│   └── [分类]/
│       └── [角色ID]/
│           ├── base.toml      # 基础属性、天赋、技能、关系、背包
│           ├── base.js        # 【可选】动态属性计算脚本
│           ├── dialogue.toml  # 常驻口上（条件触发台词）
│           ├── dialogue.js    # 【可选】动态台词脚本
│           ├── behavior.toml  # 移动倾向、自主行为规则
│           ├── behavior.js    # 【可选】复杂AI行为脚本
│           └── assets/        # 角色专属素材（头像、立绘、差分）
├── definitions/               # 全局定义库（统一定义，全模组复用）
│   ├── talents.toml           # 所有天赋/特质定义
│   ├── abilities.toml         # 所有技能/内功/被动定义
│   ├── items.toml             # 所有物品/装备/材料定义
│   ├── factions.toml          # 所有势力/门派定义
│   └── status-effects.toml    # 所有状态/buff定义
├── maps/                      # 地图数据（任意层级嵌套）
│   ├── worlds/                # 顶级大地域
│   ├── areas/                 # 中间区域
│   └── locations/             # 可交互子地点
├── quests/                    # 剧情任务
│   ├── main/                  # 主线任务
│   └── side/                  # 支线任务
├── plugins/                   # 【可选】模组专属插件
├── scripts/                   # 【可选】模组全局脚本
└── assets/                    # 全局素材（背景、UI皮肤、音效、地图底图）
```

### 2. 数据格式分工
- **引擎支持**：TOML（主力）、YAML（兼容兜底）、JS（可选脚本），自动识别格式，合并优先级：JS > TOML/YAML。
- **官方推荐分工（严格统一，不混用）**：
  1. **95%主体内容 → 统一 TOML**：角色、技能、物品、地图、剧情、口上、行为、配置；
     - 理由：语法严谨无暗坑，无缩进敏感问题，AI生成稳定，类型明确；
  2. **复杂动态逻辑 → 可选 JS 脚本**：动态属性计算、复杂AI决策、动态台词、特殊事件；
     - 理由：逻辑表达力无限，作为TOML的补充兜底，不做主力。

### 3. 核心数据关联规则（多对多原生支持）
所有关联采用**ID外键**模式：公共定义统一存放在 `definitions/`，角色/地点仅存ID+数值，无重复数据。
- 角色 ↔ 技能：角色 `abilities` 字段存技能ID + 等级，技能详情在 `abilities.toml`；
- 角色 ↔ 物品：角色 `inventory` 字段存物品ID + 数量，物品详情在 `items.toml`；
- 角色 ↔ 势力：角色 `factions` 字段存势力ID + 身份/声望，势力详情在 `factions.toml`；
- 内功 ↔ 子技能：内功定义内写 `unlocks` 解锁规则，子技能平级存放在 `abilities.toml`；
- 跨类型ID天然隔离：不同分类实体存储在独立数据池，不会互相匹配错误。

#### 示例：内功解锁层级（TOML格式）
```toml
# definitions/abilities.toml
[九阴真经]
type = "internal"
name = "九阴真经"
max_level = 10
exp_per_level = 1000

[九阴真经.base_attr]
hp = "+200"
mp = "+500"
attack = "+30"

[九阴真经.unlocks]
6 = [{ type = "ability", id = "九阴神爪" }]
9 = [{ type = "ability", id = "白蟒鞭法" }]
10 = [
  { type = "passive", id = "蛇形狸翻" },
  { type = "talent", id = "九阴神功" }
]

[九阴神爪]
type = "active"
name = "九阴神爪"
category = "爪法"
max_level = 10
damage = 150
cost_mp = 80

[[九阴神爪.effects]]
type = "debuff"
id = "九阴寒毒"
chance = 0.8
duration = 3
value = 50
```

### 4. ID命名与防重名规范
- **推荐方案（语义化，AI友好）**：同类型内ID唯一即可，跨类型允许重名；易混淆内容加语义后缀区分。
  - 示例：武功叫「九阴真经」，物品叫「九阴真经秘籍」
- **极端严谨方案（万级数据量时用）**：加类型前缀，全局绝对唯一。
  - 示例：`abl_九阴真经`、`item_九阴真经秘籍`、`tal_九阴神功`
- **兜底保障**：引擎加载时自动校验引用ID合法性，不存在的ID精准报错。

### 5. 主题与美术规范
- 基础主题变量统一在 `theme.toml` 中配置，包括主色、辅助色、背景色、文字色、字体、圆角、间距；
- 精细美术效果（纹理、边框、渐变、动画）在 `theme.css` 中实现，仅使用类选择器，不污染全局标签；
- 素材按分类存放，路径语义化，禁止中文文件名；
- 所有UI元素支持响应式，PC与手机端自动适配。

## 五、分阶段开发路线图（严格按顺序执行）
### 阶段1：项目初始化与基础架构搭建
- **目标**：搭建项目骨架，配置所有依赖，可正常启动运行。
- **核心任务**：
  1. 创建 Vue 3 + Vite + TypeScript 项目；
  2. 安装配置依赖：Pinia、Tailwind CSS、Naive UI、@iarna/toml、js-yaml（兼容用）、Dexie.js、VueUse；
  3. 建立完整目录结构（core / plugins / ui / mods / utils）；
  4. 配置路径别名、TOML/YAML文件导入支持、Tailwind主题变量基础；
  5. 配置响应式断点与基础样式重置。
- **关键产出**：可运行空项目，完整目录结构，所有依赖就绪。

### 阶段2：内核核心数据系统
- **目标**：实现数据加载、模板继承、实体管理三大地基能力。
- **核心任务**：
  1. 模组加载器：读取meta.toml、依赖检查、多模组合并加载；
  2. 模板继承系统：多级深合并、循环继承检测、深度限制；
  3. 通用实体管理系统：类型注册、按ID查询、自动校验；
  4. 数据校验工具：格式校验、ID重复检测、精准到文件行号的报错。
- **关键产出**：可加载示例模板与示例角色，模板继承正确生效。

### 阶段3：条件系统、事件总线与全局属性字典
- **目标**：实现通用条件判断、事件通信、自动字段汇总能力。
- **核心任务**：
  1. 条件表达式解析器：支持极简表达式、括号分组、错误精准提示；
  2. 全局事件总线：发布订阅、优先级、取消机制、标准事件命名规范；
  3. 条件注册器：插件可注册字段，自动汇总生成Markdown属性手册；
  4. 全局游戏上下文：统一的状态容器，供条件表达式取值。
- **关键产出**：条件解析正确，事件收发正常，属性手册自动生成更新。

### 阶段4：公共API规范与插件生命周期定义
- **目标**：定死插件运行规则与通信边界，是所有插件开发的前提。
- **核心任务**：
  1. 标准插件接口：`onLoad / onEnable / onDisable / onUnload` 四生命周期；
  2. 公共API骨架：内核基础API + 模块注册机制；
  3. 同类型插件接口约定：制定战斗、背包、地图等通用接口规范；
  4. 插件错误隔离：生命周期内错误自动捕获，单插件崩溃不影响全局；
  5. 模组依赖自动启用：根据模组meta.toml自动加载对应插件。
- **关键产出**：完整插件接口定义、公共API基类、错误隔离机制。

### 阶段5：基础UI框架、主场景与主题系统

## 六、不可突破的设计铁律
1. **内核纯净原则**：`src/core/` 内绝对禁止出现任何具体玩法、具体世界观、具体视觉相关的内容与字段。
2. **插件零直连原则**：插件之间禁止直接import、调用对方内部代码，只能通过公共API + 事件总线通信。
3. **数据与逻辑分离原则**：静态数据放TOML，动态逻辑放JS；禁止在数据里写复杂逻辑，禁止在脚本里写死大量常量。
4. **功能与主题分离原则**：UI只实现功能布局，所有视觉样式通过主题系统控制；核心代码不写死任何颜色、字体、材质。
5. **错误必提示原则**：任何数据、脚本、插件错误，必须给出精准的位置、原因、修复建议，禁止静默失败。
6. **可卸载可逆原则**：所有插件、功能都必须可以干净地禁用/卸载，不残留垃圾数据、不残留UI、不影响核心运行。
7. **同类型插件接口统一原则**：同玩法的多套插件必须遵守统一基础接口，确保模组切换插件时，上层逻辑无需修改。

## 七、最佳实践与避坑指南
1. **格式统一优先**：全量使用TOML作为主力数据格式，非必要不主动混用其他格式，降低维护与AI生成错误率。
2. **AI生成规范**：给AI的指令必须明确「只能使用属性字典里的字段」「严格按目录结构放文件」「遵循TOML语法规范」，从源头减少错误。
3. **先配置后代码**：实现功能优先考虑TOML配置方案，无法满足再上JS脚本；能用简单机制不用复杂机制。
4. **模板分层合理**：模板继承建议控制在3-4层，层级过多反而提升维护成本；通用属性往上提，专属属性往下沉。
5. **渐进式扩展**：先跑通核心玩法闭环，再逐步添加进阶功能，不要初期就堆砌大量复杂特性。
6. **主题变量全覆盖**：所有颜色、字体、尺寸、圆角必须走主题变量，禁止在组件内写死固定样式值。
