### 核心结论先给你：
你说的这个「所有可用条件的公共清单」，我们叫**全局属性字典**，它在架构里是真实存在的，而且是**自动生成、自动同步**的——你和AI不用手动维护它，加新系统/新插件它会自动更新，同时会导出一份人/AI都能直接读的说明文档，放在最显眼的位置，不用去源码里翻。

它不在模组的内容目录里（因为它是引擎能力的汇总，不是你要写的内容），但你和AI随时能拿到最新版；同时引擎自带校验，写错了会精准提示，不会出现「写了条件没反应」的黑盒情况。

## 一、它放在哪？对应到目录结构里的位置
分两层，一层是「引擎内部的注册机制」（自动运行，你不用碰），一层是「给人和AI用的可读手册」（自动生成，随手就能查）。

### 1. 引擎内部：注册与汇总（你完全不用改）
对应之前的引擎源码目录，它在**引擎内核层**，是一个统一的注册器，所有系统/插件都把自己能当条件的字段注册进来，引擎自动汇总成完整字典。
```
era-engine/src/
├── core/
│   ├── condition-registry.ts   ← 【核心】全局条件注册器，自动汇总所有可用字段
│   └── ... 其他内核模块
└── plugins/
    ├── inventory/              # 每个插件自己注册自己的字段
    │   ├── plugin.toml         # 插件配置里声明要暴露的条件字段
    │   └── ...
    └── combat/
        ├── plugin.toml
        └── ...
```

每个插件的 `plugin.toml` 里，会声明自己对外开放、可用于条件判断的字段，比如背包插件会写：
```toml
# 背包插件的 plugin.toml
id: inventory
name: 背包系统
# 注册到全局条件字典的字段
conditionFields:
  - path: inventory.{物品ID}.count
    name: 背包内指定物品的数量
    type: number
    operators: [greater_than, less_than, equal]
  - path: inventory.total_weight
    name: 背包总负重
    type: number
    operators: [greater_than, less_than]
```
引擎启动时，会自动把所有插件的这些字段收集起来，拼成完整的全局属性字典。

### 2. 给你和AI用的：自动导出的可读手册
引擎会**自动生成一份 Markdown 格式的《可用条件与属性手册》**，直接放在你最容易找到的地方：
```
era-engine/
├── mods/                      # 你的模组文件夹
├── 可用条件属性手册.md        ← 【你和AI直接看这个】自动生成，永远最新
└── ...
```

同时游戏内的**开发者面板**里，也有一个「条件字典查询」标签页，可以搜索、筛选字段，实时查看。

## 二、这份手册长什么样？人和AI一眼就能看懂
它就是一张标准的对照表，字段路径、说明、类型、能用的运算符全都列清楚，和你写条件的格式一一对应。

举个片段示例：
| 属性路径 | 中文说明 | 数据类型 | 可用运算符 | 所属系统 |
|----------|----------|----------|------------|----------|
| `player.base.hp` | 玩家当前血量 | 数值 | `>` `<` `>=` `<=` `==` | 基础属性 |
| `player.base.mp` | 玩家当前内力 | 数值 | `>` `<` `>=` `<=` `==` | 基础属性 |
| `character.{角色ID}.favor` | 指定角色对玩家的好感度 | 数值 | `>` `<` `>=` `<=` `==` | 角色关系 |
| `location.id` | 当前所在地点ID | 文本 | `==` `!=` | 地图系统 |
| `inventory.{物品ID}.count` | 背包内指定物品数量 | 数值 | `>` `<` `>=` `<=` `==` | 背包系统 |
| `game.time.hour` | 当前游戏时间小时数 | 数值 | `>` `<` `>=` `<=` `==` | 时间系统 |
| `player.talent.{天赋ID}` | 玩家是否拥有指定天赋 | 布尔 | `==true` `==false` | 天赋系统 |

你写条件的时候，直接抄左边的「属性路径」就行，比如：
```toml
conditions:
  - player.base.hp < 30
  - inventory.止血草.count >= 2
  - game.time.hour >= 20
```
和手册里的路径完全对应，不用任何转换。

## 三、它怎么保证自动同步？加新系统/删系统不用手动改
完全是自动化的，不需要你维护：
1. **加插件/加系统时**：新插件在自己的 `plugin.toml` 里声明要暴露的字段，引擎启动时自动收录进字典，同时自动更新《可用条件属性手册》。
   - 比如你加了魔药插件，手册里会自动多出 `player.skill.potion.level`（炼药等级）、`cauldron.temperature`（药炉温度）这类新字段。
2. **删插件/关系统时**：对应字段自动从字典里移除，手册同步更新，不会残留无效字段。
3. **模组加自定义字段时**：模组自己的脚本里注册的字段，也会自动合并进字典，只在该模组生效。

简单说：**你加什么功能，它就自动多出什么条件；删什么功能，对应条件自动消失**，永远和当前启用的内容完全一致，不会出现过时、对不上的情况。

## 四、AI怎么用它？准确率拉满的用法
你担心的「AI不知道能写什么条件」，靠这份手册就能100%解决，而且操作非常简单，两种用法：

### 用法1：生成内容前，先把手册喂给AI
每次让AI写角色、写剧情、写事件之前，先把最新的《可用条件属性手册》丢给它，再加一句要求：
> 所有条件只能使用手册里列出的属性路径，禁止编造不存在的字段；条件统一用极简表达式写法。

AI就会严格按照手册里的字段来写，不会瞎编，准确率接近100%。

### 用法2：引擎端兜底校验
就算AI偶尔写错了，引擎加载数据时也会自动校验，精准报错：
> 【错误】quest_linghuchong.toml 第15行：条件字段 `player.酒量` 不存在
> 可参考《可用条件属性手册》查看所有合法字段

不会出现「写了条件没反应、不知道错在哪」的情况，一眼就能定位修正。

## 六、补充：为什么它不放在模组目录里？
因为它是「当前所有启用功能的能力汇总」，不是模组内容本身：
- 不同模组启用的插件不一样，可用条件也不一样，引擎会根据当前模组自动生成对应版本的手册；
- 它是引擎自动维护的，不需要你手动编辑，放在模组外面、自动生成，反而最省心，不会出现「手册和实际不同步」的问题。
